# Conciseness — answer short, then stop

The owner reads these replies. Long walls of reasoning cost them time and bury the answer.

- **Lead with the answer.** The verdict comes first, in one or two sentences.
- **Then the minimum evidence** that makes the verdict checkable — a file path, a line number,
  a one-line code quote. Not a walkthrough of how you found it.
- **No re-explaining the code you were asked about** unless the answer depends on it.
- **No restating the request, no "Situation" essay.** A two-line scope note is enough.
- **No option tables with five rows** when one recommendation and one fallback will do.
- **No closing summary** of what you just said.
- Hard ceiling for a non-trivial reply: **~200 words**. Go over only when the answer is genuinely
  a list of distinct items (a diff summary, a file inventory), and then use bullets, not prose.
- Questions that need a decision: state **what you would do**, not every alternative you rejected.
